# Подпись и проверка пакета macOS

В исходных пакетах 5.1.0.6 и 5.1.0.7 подписи Qt-плагинов не соответствовали их страницам. На Mac владельца это дало CODESIGNING / Invalid Page. CPack пропускал окончательную подпись, если CODESIGN_SIGNATURE не задана.

Теперь cmake/sign_binaries.cmake вызывает sign_bundle.py для локальной ad-hoc подписи, если сертификат не указан. Сначала подписываются вложенные файлы, включая служебные данные в Contents/MacOS; затем framework и bundle. Для данных вне формата Mach-O подпись хранится в расширенных атрибутах, поэтому обязательна проверка после извлечения конечного PKG.

check_package.py извлекает готовый PKG, проверяет все архитектуры через codesign --verify --all-architectures --deep --strict и с --launch запускает приложение нативно на15секунд, сохраняет журнал и снимок. Это проверка запуска, а не VPN-сессии и не нотариального заверения Apple.

repair_package.py исправляет подписи в уже собранном PKG, сохраняет исходные компоненты/скрипты/Distribution и переупаковывает. Workflow bee-lazy-macos-repair.yml использует зафиксированные байты исходного артефакта5.1.0.7 и проверяет его SHA256.

Проверенный результат macfix1: исходник приложения6d4fe70, перепаковка0bb76d9, workflow42965567336 на macOS26 ARM64. Исходный PKG не проходит codesign; исправленный конечный PKG проходит. На снимке видно окно Bee Lazy со стартовым экраном; процесс работает15секунд. Независимая проверка198архитектурных частей Mach-O:0безподписи,0повреждённых страниц. У первоначального5.1.0.7 было92несоответствия страниц подписи.

Выпуск: https://github.com/rifatshava/bee-lazy-vpn/releases/tag/v5.1.0.7-beelazy.macfix1 . Старые Mac-пакеты без macfix1 не использовать. Коммерческого Developer ID и нотариального заверения в macfix1 нет.
